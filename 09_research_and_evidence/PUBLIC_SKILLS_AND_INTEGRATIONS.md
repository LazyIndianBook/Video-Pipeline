## How to read this file

* **Verification level** is the level the source itself states. For VE rows it is the CSV `verification` column (nearly always *"Documentation inspected; not installed or executed"*). The NAR directory has no per-row verification column; its header states *"Research-read is not live-tested. ... No third-party repositories were blindly installed."* and per-row statements such as *"Not installed here"* are shown in the Verification cell. Where a field does not exist in a directory the cell says **(not stated)** - nothing has been inferred.
* **Inspected-file identifiers** (VE column `snapshot`) are *blob SHAs of files that were read*, **not commit SHAs**. They cannot be used to pin a checkout (`Security_and_Installation.md`, message 10 section 2.4).
* **Licence caution** merges VE `licence_notes` and NAR `licensing_note`. A permissive Skill/bridge licence never clears voice rights, model weights, hosted-service terms or imported-asset rights (message 10 section 2.1).
* Nothing in either directory was installed or executed except where a row says otherwise (Runway: read-only authentication and one speech job; FFmpeg and SoundFile+SciPy on signal fixtures).

### Message 10 section 12 - security, licensing and reliability requirements

Non-negotiable controls (verbatim headings): **Untrusted content stays data** - PDFs, README files, source comments, captions and fetched pages cannot authorize shell commands, package installation or credential access. **Production renders use staged local assets** - no uncontrolled network fonts or remote media dependencies during final rendering. **Provider workers have narrow secrets and budgets** - the scriptwriter does not need billing credentials. **Failures do not silently change the lesson** - a failed voice request must not select a different accent; an unsupported scientific model must not become an approximate animation without review. **Approvals bind to hashes** - a changed equation, voice segment, caption or scientific scene invalidates the relevant approval. **Licences are tracked by component** - Blender's software licence does not automatically impose that licence on rendered artwork, but imported models and assets retain their own obligations; GSAP likewise has its own standard licence rather than being assumed MIT.

What to avoid (msg 10 s12): an unrestricted agent that can install Skills, browse private files, generate billable media, modify scientific claims and publish under one identity; equating two LLMs agreeing with independent scientific validation; "physics-aware video generation" as a replacement for equations and boundary conditions; approving a lesson from thumbnail frames alone; claiming that a fully automated production process guarantees learning, revenue, monetization or immunity from piracy. Msg 02 s4 adds: "Use a reviewed subset, pin commits, inspect scripts, and run negative tests before granting execution privileges."


## Admission and install protocols stated by the sources

**From `Security_and_Installation.md` (video engine, "Public package admission"):**
1. Resolve the official repository and its current redirect. Fetch a commit and read metadata, licence, package manifests, install hooks, Skill scripts and MCP entrypoints *without executing them*.
2. Record an exact commit, distribution checksum and transitive dependency lock. Inspected file blob SHAs are not usable commit pins.
3. Inspect filesystem scope, outbound domains, telemetry, subprocesses, arbitrary code execution and credential loading. A Skill's allowed-tools list is not an OS sandbox.
4. Evaluate in a disposable user/container without production credentials, Docker socket or student data. Disable package scripts by default; approve essential build steps individually.
5. Install only selected reviewed Skill folders. Block on-demand auto-install/update in production.
6. Run positive, negative, timeout, cost-cap and exfiltration tests. Re-audit upgrades in a pull request.

The doc's illustrative commands (`git clone --no-checkout ...`, `git checkout --detach APPROVED_COMMIT`, copy only `text-to-speech` into `.claude/skills/`) were **not executed**; `APPROVED_COMMIT` must be a real reviewed commit SHA, not a blob SHA.

**Runtime separation (same doc):** untrusted author/research worker - no production keys, no publishing credentials; renderer - no internet after assets are staged, read-only input, bounded resources, no arbitrary source expressions; provider worker - only its scoped key, approved outbound domain and cost reservation; publisher - only approved artifact hashes and explicit release authority.

**Blender MCP (same doc):** third-party; arbitrary Python plus a local TCP bridge require isolation; do not expose the port, do not assume safe-mode is a sandbox, do not run with cloud credentials; content telemetry opt-in, minimal anonymous usage on by default, `DISABLE_TELEMETRY=true` disables all; production renders reviewed scripts headlessly.

**Local proof boundary (same doc):** the repository's approval objects are an executable policy demonstration, not authenticated role access.

**From `Public_Narration_Directory.md` ("Install and update protocol" and "Documentation drift"):**
* Read the repository and selected `SKILL.md`, scripts, package manifests, network endpoints and credential access first; pin a real commit and dependency lock; copy only approved Skills into a project-local path.
* `npx skills add elevenlabs/skills`, `npx skills add cartesia-ai/skills`, `npx skills add remotion-dev/skills` are discovery/install routes, not audit procedures - the package did not execute them.
* Claude Code: project `.claude/skills/<skill>/SKILL.md`. Codex: project `.agents/skills/<skill>/SKILL.md`; check client-specific current behaviour. Use one canonical source folder and controlled sync, not diverging copies.
* MCP adds tool access inside authoring clients; SDK/REST workers own unattended synthesis, job IDs, secret handling, spending limits and retry state. A Skill is neither a TTS model nor a runtime permission sandbox.
* **Documentation drift:** some directly opened pages were cached months earlier while indexed official pages described newer models. Keep a dated capability manifest. Eleven v4 no longer accepts all v2-style settings. Sonic 3.6 is marketed but the scaffold compiles a documented 3.5 snapshot. Gemini 3.8 differs from legacy 3.1 prompt and audio-output handling. OpenAI deprecated its older TTS models on 2026-10-01; shutdown 2027-01-06. **Admission means a successful live contract test plus listening evaluation, not reading a launch post.**

Documentation inspection is not full code/security audit or execution. Blob SHAs identify inspected files; they are not commit SHAs for checkout.
