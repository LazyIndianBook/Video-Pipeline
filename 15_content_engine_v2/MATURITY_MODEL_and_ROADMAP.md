# Maturity Roadmap

## 1. Maturity levels 0–5

KPIs are *defined* here. Thresholds are set from the baseline measured at the previous level and recorded as registry policy; none are invented in this plan. A level is reached only when its exit gate passes. No level starts with a red regression suite (56 engine tests, 60 narration tests (2 need FFmpeg; all 60 must pass in the pinned container), schema golden fixtures and golden renders).

## 3. Build order (what first, and why)

The order follows three constraints: never break the working cell, prove the core loop on one lesson before widening, and widen along the axis that exercises the most new rules per unit of effort.

1. **Close level 0.** Run the 56 + 60 tests and one pilot render in the pinned container; close section 14 fixes; record container, Chrome, FFmpeg, HarfBuzz and font digests in `harness/` (O-16). *Why first:* every later gate compares against this baseline.
2. **Schemas, lint and hash canon (level 1).** Add a CI step that compiles every schema with a draft-07 validator and runs the golden fixtures (positive and negative); add the commercial-term lint; implement JCS+NFC hashing in Python and Node with the cross-language golden test. *Why:* every later record depends on stable validation and hashes. A wrong hash canon would cause false invalidation storms later. Add draft-07 schemas (additionalProperties: false, with positive and negative fixtures in the same CI step) for every record M1 writes that has none: ~~`curriculum_framework` (Architecture §2.6),~~ `storyboard` / H-SB record (RD-46 bound fields) and `ledger_row` (§9.2 row types). `epp` (§3.5), `format_plan` (§5.1 step 6), `approval_record` (§3.7) and `locale_profile` (CE-40; TEMPLATES §5) were added to `schemas/` on 15 Oct 2026 and get their fixtures in the same step, as do `curriculum_framework` (Architecture §2.6; CE-111, P1-14) and `learning_signal` (Architecture §9.7; CE-117), added later the same day from the completeness critic. Do the same for every registry kind in §3.1 and the CE-63 addendum that has none (`safety/`, `a11y/`, `overlay/`, `slot/`, `model/`, `kit/`, `harness/`, `reviewer/`, `budget/`; P1-11; `lex/` and `gs/` got `subsystems/schemas/lex_entry.schema.json` and `golden_set.schema.json` on 15 Oct 2026). (Step widened 15 Oct 2026.)
3. **Registries seeded with today's behaviour.** `level/l9_10`, `level/l11_12`, `format/detailed`, `format/short`, `family/stem_fixture`, `persona/super-teacher`, `safety/ac1`, `a11y/base`, `style/*` (12's five guides), `locale/en-in`, `locale/hinglish`, `locale/hi-in`, `voice/*` with licence evidence, `model/*`, `kit/*`, `harness/*`, `reviewer/*`. *Why:* a zero-behaviour-change port proves the registries describe reality before they change it.
4. **v1 import and approval closure.** Run the converter on the pilots; wrap v1 approvals as legacy approvals; build the dependency index and release check. *Why:* without it every existing artefact fails v2 release.
5. **Curriculum Graph + Lesson Graph for one chapter; Resolver and Compiler; M1.** *Why:* this is the core loop. It must be proven on one lesson before any new format exists.
6. **Derived formats (level 3).** Simplified, Recap and Question Analysis first (the founder's named types), then Worked Example, Misconception Fix, Concept Intro, Flashcard Reel, Practice Set and Series. *Why:* these reuse the same graph and family, so they isolate the format engine and GA-Δ economics.
7. **First non-STEM family and Middle Stage (level 4).** Humanities on Class 10 social science, then level/l6_8 for STEM and social science. *Why:* exercises the claim ledger, contested states, maps and sensitivity review, which are the hardest accuracy rules, while staying in AC1.
8. **Locales.** String-table externalisation proven on hi-IN and Hinglish; GL-glossary per family; GL-voice decision (O-12); then Assamese with a human voice.
9. **Class 1–5 (level 5a).** Only after O-1 to O-4, O-7 and O-10, the G-COUNSEL record and an onboarded child-development reviewer with a backup. Junior persona, Path A recordings, Story/Song, Activity, Read-Along.
10. **UG/PG, competitive, vocational (level 5b).** 16:9 Lecture Segment (after O-19), Derivation/Proof, Viva Prep, overlays, voc (after O-11).

**Deliberately deferred (YAGNI):** a graph database, a workflow engine, a CASE REST service, a sign-language track, derivative sampling of human gates (rejected outright), and dashboards beyond ledger queries. Each has a stated trigger in the Decisions register.

## 6. Governance cadence

- **Weekly:** gate queue, re-QA backlog, ledger capacity lines (reviewer minutes, Path A studio minutes); on-call rota for `reviewer/on-call` (primary plus backup, handed over weekly; Architecture §9.6, CE-115; level-2, added 15 Oct 2026).
- **Monthly:** cost reconciliation against invoices; defect-escape review with time-to-withdraw per severity from `incident` ledger rows and the post-incident review entries (CE-115; added 15 Oct 2026); GR impact previews scheduled.
- **Quarterly:** slot-vocabulary review (merge near-duplicates); Kit requalification check; evidence register update (pilot results change Hypothesis tags through new profile versions); section 14-style audit at each maturity gate; restore drill from backups only, with an equal MP4 SHA-256 for a sampled released artefact (CE-114; from M1 onward; added 15 Oct 2026); Q-REPR representation report per level × family × locale, report-only, feeding the next quarter's authoring brief (CE-121; level-3+; added 15 Oct 2026).
- **Exam-window calendar (CE-122; level-3+; added 15 Oct 2026):** the `exam_windows[]` on overlay entries and board frameworks form the freeze calendar. Inside any window touching an entry's affected set, only Revocation, Safety-tightening and S1 incident fixes release; other GR changes queue and the impact preview shows the deferral date. At T-10 weeks before each window [Recommendation], the surge playbook runs: plan and gate Recap, Revision Sheet, Practice Set and Paper Walkthrough for in-window competencies so the window needs no new GA-Graph work, confirm the reviewer rota with backups for the window, forecast gate-minutes against the rota from the ledger capacity lines, and staff on-call for the whole window. This also mitigates Architecture §11 risk 1 (review capacity) and risk 5 (invalidation storms) during exam season.
