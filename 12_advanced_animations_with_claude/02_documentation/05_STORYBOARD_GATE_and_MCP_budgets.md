# 05 · The storyboard gate and MCP budgets

**Purpose.** Specify the mandatory human gate that stops an animation job before any paid asset or scene code (the 3×3 storyboard grid, `beats.json`, `estimate.json` and an approval record bound to hashes), and the controls around external generation services: how Higgsfield is connected and what it costs, the credit and token ledger, per-job MCP permissions, keys, other MCPs (Blender, ElevenLabs, music), character consistency, and the rule that labelled science never comes from an image model.

**Read with.** `12_advanced_animations_with_claude/06_prompts_and_templates/storyboard_request.md`, `12_advanced_animations_with_claude/06_prompts_and_templates/review_checkpoint.md`, `12_advanced_animations_with_claude/03_skills/examleaf-anim-storyboard-gate/`, `12_advanced_animations_with_claude/03_skills/examleaf-mcp-orchestrator/`, `12_advanced_animations_with_claude/03_skills/examleaf-effort-governor/`, `07_end_to_end_pipeline_instructions/08_COST_TRACKING_and_BUDGETS.md`, `07_end_to_end_pipeline_instructions/07_SECURITY_CREDENTIALS_and_SKILL_ADMISSION.md`, and `04_video_engine/implementation_v2/docs/Higgsfield_Findings.md`.

**Conventions.** As in doc 00. Edge cases #1–#65 from report §8. Figures labelled "competitor-authored" come from a Higgsfield competitor's blog [N75]–[N80] and are not verified prices.

## 1. Why the gate exists and where it sits

[V4]'s master prompt stops the agent after the script and the storyboard: "⛔ Review checkpoint. Stop after Steps 2 and 3. Show me the script and the storyboard grid, then wait for my approval before continuing." The checkpoint exists to avoid spending credits and hours on visuals the human would reject (#47). In ExamLeaf the script is already approved upstream (GA), so the gate approves **visuals, scope and cost**.

**Position in the pipeline** [Recommendation]:

```text
GA academic approval of the script bundle (existing)
  → examleaf-storyboard-route tags scenes (existing; extended for illustrative/typographic routes)
  → examleaf-anim-storyboard-gate builds: grid + beats.json + estimate.json
  → ⛔ STORYBOARD GATE: human approves visuals + estimate; record bound to hashes
  → narration synthesis + alignment (existing) → cue sheets
  → paid assets (only those listed in the approved estimate) via examleaf-mcp-orchestrator
  → briefs → scene code → render → QA → GF/GS
```

What may happen **before** approval: code-rendered thumbnails, token-only planning text, and (only if the estimate for it was approved separately as look-dev) one Higgsfield grid. What may **not** happen before approval: any cutout, background, voice or video generation; any scene-code job.

**Who approves.** For pilots: the founder (cost) and the academic lead (fit with the approved script). Approvals are recorded by the approval mechanism of RD-17 (minimum authenticated approval service in P2); agents assemble evidence but never write approvals (`07_end_to_end_pipeline_instructions/06_QA_GATES_and_RELEASE.md`; RD-17).

## 2. The 3×3 grid

### 2.1 Shape

- **One grid per illustrative segment** of a lesson (hook, analogy, recap) and **one per Reel**. Data-bound scenes do not need a grid; their key frames come from the existing renderers and are reviewed under GA/GF.
- Nine **vertical 9:16 panels** in beat order, arranged 3 across × 3 down. Nine 9:16 panels in a 3×3 arrangement make a grid that is itself 9:16 (for example nine 360×640 panels in a 1080×1920 sheet, before gutters), so the reviewer judges compositions in their real shape (doc 03 §3.2 rule 9).
- Thin gutters ([V4-MP] uses "thin cream gutters") and a **panel number tag added in code**, never generated by the image model (#54).
- A short caption under each panel (in the review sheet, not on the panel) quoting the beat's approved sentence ID and the visual intent.

### 2.2 Path A: code-rendered thumbnails (default, free)

1. `examleaf-anim-storyboard-gate` writes a "blocking" scene per beat: style background, placeholder silhouettes for characters and props, code-built titles and tags, and for any science element a key frame rendered from the fixture by the owning skill (SVG/Manim).
2. Each beat is seeked at its key time through the harness (doc 04) and captured as a 1080×1920 still.
3. The nine stills are tiled into one sheet (FFmpeg's `tile` filter is a standard way to do this; verify the exact options on your build) and the number tags are drawn in code.
4. Cost: tokens only (planning-level effort, doc 01 §7.2), no credits.

### 2.3 Path B: Higgsfield GPT Image 2.5 grid (only when needed)

**When allowed:** a new collage character or a new background family needs look-development and code silhouettes cannot show what the reviewer must judge (for example, the first lesson in `paper-collage-vertical`, or a new recurring hero).

**How** ([V4-MP] steps 3 and §12, adapted):
1. Estimate and reserve credits first (§7). A grid is one generation; its credit cost for `gpt_image_2_5` is not in the evidence (verify, Q5).
2. Prompt = the style description + nine panel descriptions in order + "no text, no letters, no numbers, no labels" (#54) + the vertical panel shape. Whether the model supports a 9:16 output size natively is not verified; if not, generate the nearest supported size and pad, rather than generating nine separate images (which multiplies credits).
3. The canonical hero reference image (if one exists) is attached for consistency (#48).
4. The returned image is stored with its provider job ID, prompt hash and model ID in the AssetManifest, quarantined until approved.
5. Number tags and captions are added in code on the review sheet.

### 2.4 What the reviewer checks on the grid

| Check | Fails when |
|---|---|
| Every panel maps to an approved sentence (one sentence = one beat, [V4-MP]) | A panel shows something the script does not say |
| Science elements (if any) match the fixtures' key states | A ray, graph, count or structure is drawn differently from the approved data |
| No text or formula inside generated imagery | Any glyph in a generated panel (#54) |
| Vertical composition respects the bands (title / content / caption) | Essential content sits in the caption band (#51) |
| Character consistency | The hero changes design between panels (#48) |
| Style fit and depth | Flat, generic or off-style ([V2] "flat"; #8) |
| Cost and asset count match `estimate.json` | Panels imply assets not in the estimate |

## 3. `beats.json`

One file per grid. Example [Recommendation; the skill's template in `12_advanced_animations_with_claude/03_skills/examleaf-anim-storyboard-gate/templates/` is authoritative]:

```json
{
  "grid_id": "chem11-atom-recap-g1",
  "lesson_id": "asseb-c11-chem-structure-of-atom",
  "style": {"id": "paper-collage-vertical", "version": "1"},
  "script_bundle_sha256": "<GA-approved bundle hash>",
  "beats": [
    {
      "panel": 1,
      "beat_id": "r01",
      "sentence_ids": ["S41"],
      "route": "illustrative",
      "visual_intent": "Ransom-note question title; hero kid looks up from bottom of content band",
      "science_elements": [],
      "assets": [
        {"asset_id": "hero_kid_pose_lookup", "source": "generated", "provider": "higgsfield", "status": "needed"},
        {"asset_id": "bg_cream_watercolour", "source": "generated", "provider": "higgsfield", "status": "reuse_if_approved"}
      ],
      "code_elements": ["ransom_title", "sparkle_doodles"],
      "cue_ids": ["title_reveal"],
      "estimated_duration_s": 4.5
    },
    {
      "panel": 4,
      "beat_id": "r04",
      "sentence_ids": ["S44"],
      "route": "illustrative_with_science",
      "visual_intent": "Most particles pass through the foil; a few bounce back",
      "science_elements": [{"fixture": "fixtures/rutherford_recap.json", "fields": ["claims[C12].display_text"]}],
      "assets": [{"asset_id": "gold_foil_sheet", "source": "generated", "provider": "higgsfield", "status": "needed"}],
      "code_elements": ["particle_paths", "claim_tag_C12"],
      "cue_ids": ["particles_fire", "few_bounce"],
      "estimated_duration_s": 6.0
    }
  ]
}
```

**Rules.**
1. `sentence_ids` reference the approved script; beats never contain narration text written by an agent (#11).
2. `estimated_duration_s` comes from `examleaf-pacing-controller` estimates; the final duration comes later from real narration (doc 02 §3.4).
3. Every `science_elements` entry names fixture fields; an empty list means the beat may not display science (accuracy invariant).
4. Every generated asset is listed; anything not listed cannot be generated later without a new approval.
5. Reuse is explicit (`reuse_if_approved`) so credits are not spent twice on the same background.

## 4. `estimate.json` (tokens and credits)

### 4.1 Example

```json
{

  "grid_id": "chem11-atom-recap-g1",
  "brief_template_version": "1",
  "units": {"tokens": "count", "credits": "higgsfield_credits", "usd": "derived_where_known"},
  "agent_work": [
    {"task": "scene_code", "scene_ids": ["r01","r02","r03","r04","r05"],
     "model": "<pinned Opus 5.5 ID>", "effort": "high", "max_fix_loops": 3,
     "tokens_estimate": {"input": null, "output": null},
     "basis": "pilot median per scene once measured; until then a stated upper bound",
     "upper_bound_note": "[V1]: ~78K (low) to ~625K (max) tokens for a whole 79 s piece built from scratch"}
  ],
  "generated_assets": [
    {"asset_id": "hero_kid_pose_lookup", "provider": "higgsfield", "model": "gpt_image_2_5",
     "count": 1, "credits_each": null, "credits_bound": "<approved bound>",
     "basis": "per-model credit cost not verified; separate approved bound (Higgsfield_Findings)"},
    {"asset_id": "gold_foil_sheet", "provider": "higgsfield", "model": "gpt_image_2_5",
     "count": 1, "credits_each": null, "credits_bound": "<approved bound>"}
  ],
  "regeneration_allowance": {"assets": 1, "reason": "one retry for character drift (#48)"},
  "render_minutes_estimate": null,
  "human_minutes_estimate": {"storyboard_review": null, "final_review": "per 08_COST_TRACKING"},
  "caps": {"tokens": "<cap>", "credits": "<cap>", "usd": "<stage cap per RD-40>"},
  "overrun_policy": "hard stop; founder approval recorded in the ledger (RD-40)",
  "confidence": "low until pilot measurements exist"
}
```

### 4.2 How the estimate is built

1. **Count first.** Scenes × expected fix loops; assets × (1 + regeneration allowance); render minutes from the benchmark.
2. **Tokens.** Use pilot medians per scene type once measured. Before that, state an upper bound and its basis. [V1]'s figures are an upper-bound reference for a whole piece built from scratch with no guides; [Hypothesis] template-based ExamLeaf scenes should land far below them (report §3.3). Thinking cannot be disabled on 5.5 models [N26] (#5), so the estimate includes thinking tokens.
3. **Credits.** Per-model credit costs are not verified (Q5). "Some operations do not support cost estimation; those need a separate approved bound rather than an invented price" (`04_video_engine/implementation_v2/docs/Higgsfield_Findings.md`). So each generated asset carries either a measured cost or an explicitly approved bound.
4. **Dollars.** Derived only where a verified price exists. Model names and prices are editable inputs (RD-04).
5. **Caps.** Per-stage caps follow RD-40: initial cap = modelled line; anything beyond needs a founder approval recorded in the ledger. The existing generated-stills line is $0.20 per lesson and generated video defaults to **0 s** (RD-39) (`07_end_to_end_pipeline_instructions/08_COST_TRACKING_and_BUDGETS.md` §1). Collage-heavy lessons will exceed the stills line; that is exactly what the gate makes visible.
6. **Providers config.** The engine's `04_video_engine/implementation_v2/configs/providers.example.json` already sets Higgsfield `enabled: false`, `max_scene_estimate_cents: 200` and `requires_live_model_schema: true`; keep those defaults until a provider worker is admitted.

### 5.1 Fields [Recommendation]

```json
{
  "approval_id": "appr-sb-chem11-atom-recap-g1-001",
  "gate": "storyboard",
  "decision": "approved | approved_with_conditions | rejected",
  "conditions": ["regenerate panel 6 hero pose only", "no dark sheets"],
  "approvers": [
    {"identity": "<authenticated id>", "role": "founder", "scope": "cost"},
    {"identity": "<authenticated id>", "role": "academic_lead", "scope": "fit with approved script and fixtures"}
  ],
  "bound_hashes": {
    "grid_png_sha256": "<…>",
    "beats_json_sha256": "<…>",
    "estimate_json_sha256": "<…>",
    "script_bundle_sha256": "<…>",
    "style_guide_version": "paper-collage-vertical@1",
    "style_file_sha256": "<…>",
    "hero_reference_sha256": "<…>",
    "fixtures_manifest_sha256": "<…>"
  },
  "approved_caps": {"tokens": "<cap>", "credits": "<cap>"},
  "timestamp": "<ISO 8601>",
  "signature": "<approval service signature>"
}
```

### 5.2 Invalidation

Any change to a bound artefact invalidates the approval: a new beat, a different style version, a changed asset list, a higher estimate, a changed script bundle or fixture. This follows the project rule "Approvals bind to hashes. A changed equation, voice segment, caption, or scientific scene invalidates the relevant approval" (`07_end_to_end_pipeline_instructions/07_SECURITY_CREDENTIALS_and_SKILL_ADMISSION.md` §3). Fix-loop notes do not invalidate; scope changes do.

### 5.3 Enforcement

- `examleaf-anim-brief` refuses to build a brief whose input hashes do not match an approval record (doc 02 §7.2).
- `examleaf-mcp-orchestrator` refuses any generation not listed in the approved `beats.json`/`estimate.json`.
- Approvals are written only by the approval service; local JSON is a "policy demonstration, not authenticated role access" (RD-17).
- *15 Oct 2026 (audit M10; RD-46).* The skill template `examleaf-anim-storyboard-gate/templates/approval_record.json` now follows §5.1: two roles (`founder` for cost, `academic_lead` for science fit, two identities), `fixture_hashes`, `style_hash` and `hero_hash`, all bound. `estimate_and_gate.py --verify-approval` checks both roles and re-hashes estimate, beats, grid, script, fixtures, style and hero. It runs in the **runner**, which first verifies each identity and the signature against the authenticated service; the agent's job settings deny `Edit(./storyboard/**)` (doc 01 §7.4).

## 7. The ledger design

### 7.1 Reuse what exists

The engine already has a tested local ledger: `04_video_engine/implementation_v2/src/examleaf/budget.py` (SQLite, integer units, `BEGIN IMMEDIATE`). Its behaviour (`07_end_to_end_pipeline_instructions/08_COST_TRACKING_and_BUDGETS.md` §2):
- `reserve(key, amount)`: same key + same amount → no-op (idempotent); same key + different amount → error; sum over limit → refused.
- `settle(key, actual)`: records the actual amount even on overrun, then raises "vendor overrun recorded; production must pause".
- Known gap: no `release` transition for cancelled reservations (build item).

[Recommendation] Use **one ledger per unit**: the existing cents ledger for dollars, a second instance whose integer unit is **one Higgsfield credit**, and a third for **tokens** (thousands of tokens as the integer unit). The class is unit-agnostic in practice (it stores integers); a small build item adds a `unit` column and the `release` transition. Do not add a new ledger library.

The existing `ProviderJob` contract (`idempotency_key`, `provider`, `model`, `provider_job_id`, `state` ∈ planned/reserved/submitted/running/succeeded/failed/unknown, `estimated_cents`, `actual_cents`, `input_sha256`) and the rule "persist provider job ID; do not resubmit an unknown job" apply unchanged.

### 7.2 Call sequence for one paid generation

The sequence below follows `04_video_engine/implementation_v2/docs/Higgsfield_Findings.md` ("model discovery → complete request estimate → attempt reserve → explicit budget → request/job persistence → actual invoice reconciliation") and adds the gate checks.

1. **Gate check.** The asset ID is in an approved `beats.json` and `estimate.json`; the approval record's hashes match (§5).
2. **Model discovery.** Confirm the model ID and its live schema (`requires_live_model_schema: true` in `04_video_engine/implementation_v2/configs/providers.example.json`).
3. **Estimate.** Measured cost if known; otherwise the approved bound.
4. **Idempotency key.** `sha256(job_id + asset_id + prompt_sha256 + reference_sha256 + model_id + attempt_no)`. The same request always produces the same key.
5. **Reserve** in the credit ledger. Refused → stop; nothing is sent (#42).
6. **Persist** a `ProviderJob` row in state `reserved`, then submit **once**; persist the provider job ID as soon as it is returned (`submitted`).
7. **Wait for the result window.** Results usually arrive within 60 s of job completion [N35]; poll with a deadline, not a tight loop.
8. **Unknown state** (timeout, lost connection): mark `unknown`, **reconcile** via the provider's usage view (Manage Account → Usage [N35]) or API; never resubmit an unknown job (#43).
9. **Settle** with the actual credits. An overrun is recorded honestly and pauses generation (`settle` raises) (#42).
10. **Store and quarantine** the asset with provider job ID, prompt hash, model, cost and terms in the AssetManifest.
11. **Retry policy** for `failed` (not `unknown`): at most the approved regeneration allowance; exponential backoff between attempts; a new attempt number means a new idempotency key and a new reservation (#44). Throttling responses lengthen the backoff and move batches off-peak [N80].
12. **Daily reconciliation**: match every settled job against the provider's usage export; mismatches freeze generation for that provider until resolved (`07_end_to_end_pipeline_instructions/08_COST_TRACKING_and_BUDGETS.md` §2).

### 7.3 Pseudocode (stdlib only; provider call left abstract because the CLI/API surface is unverified)

```python
import hashlib, json, time

def idem_key(job_id, asset_id, prompt, ref_sha, model_id, attempt):
    raw = json.dumps([job_id, asset_id, hashlib.sha256(prompt.encode()).hexdigest(),
                      ref_sha, model_id, attempt], separators=(",", ":"))
    return hashlib.sha256(raw.encode()).hexdigest()

def generate_asset(gate, ledger, jobs, provider, req, max_attempts, deadline_s=600):
    if not gate.is_approved(req.asset_id):                  # §5: listed and hash-bound
        raise PermissionError("asset not in approved storyboard/estimate")
    for attempt in range(1, max_attempts + 1):
        key = idem_key(req.job_id, req.asset_id, req.prompt, req.ref_sha, req.model_id, attempt)
        ledger.reserve(key, req.credits_bound)               # raises if cap would be exceeded (#42)
        job = jobs.get_or_create(key, state="reserved", estimate=req.credits_bound)
        if job.state == "succeeded":
            return jobs.cached_result(job)                   # same request already paid for
        if job.state == "failed":
            continue                                         # this attempt is spent; next attempt, new key
        if job.state in ("submitted", "running", "unknown"):
            return jobs.reconcile(job)                       # never resubmit (#43)
        job.provider_job_id = provider.submit(req)           # abstract: verified CLI/API call only
        jobs.save(job, state="submitted")
        result = provider.wait(job.provider_job_id, deadline_s)   # poll with a deadline
        if result is None:
            jobs.save(job, state="unknown")                  # reconcile later via usage view [N35]
            raise TimeoutError("unknown state; reconcile before any retry")
        ledger.settle(key, result.actual_credits)            # raises on overrun -> pause
        if result.ok:
            jobs.save(job, state="succeeded")
            return result
        jobs.save(job, state="failed")
        time.sleep(min(300, 15 * 2 ** (attempt - 1)))        # backoff; throttling (#44)
    raise RuntimeError("regeneration allowance exhausted; human review")
```

The real implementation belongs in `12_advanced_animations_with_claude/03_skills/examleaf-mcp-orchestrator/scripts/` with its own tests; this block only fixes the order of operations.

### 7.4 Token ledger for Claude Code

1. `examleaf-effort-governor` reserves a per-scene token budget before launching a job, based on `estimate.json`.
2. After each run it settles the actual tokens from the run log (doc 01 §7.5).
3. When a scene reaches its cap, the next fix loop does not start; the job reports (doc 02 §3.16).
4. Ultracode is refused outright (#3); its multi-agent cache behaviour in [V1] ("each sub-agent built its own cache… restarted fresh") makes token use unbounded.
5. Thinking tokens are included (#5); Haiku prompts are kept under 100K tokens (#61).

## 8. Permissions per job and secrets

### 8.1 Who may call what

| Worker | MCP / provider tools | Keys | Network |
|---|---|---|---|
| Scene job (Claude Code in `anim_jobs/<lesson>/<job>/`) | **None** | None | None needed (deny web tools, doc 01 §7.4) |
| Storyboard job (Path A) | None | None | None |
| Provider worker (`examleaf-mcp-orchestrator`) | Higgsfield CLI or API, only the operations listed for the job | Higgsfield key only, from the worker's secret store | Higgsfield domain only |
| Narration provider worker (existing) | TTS provider only | TTS key only | TTS domain only |
| Render box | None | None | None after staging |
| Supervised look-dev session (optional) | Higgsfield MCP enabled for that session only | User login, not stored in the repo | Higgsfield |

[V3] granted "full permission to use all the MCPs we currently have connected" for a demo; that is never done in ExamLeaf (#41, #42).

### 8.2 Enabling an MCP for exactly one job

1. Admit the MCP or CLI (doc 01 §5).
2. Configure it in the **provider worker's** project settings, not in the scene package and not user-global.
3. Allow only the tool names the job needs; deny the rest (verify the permission syntax for MCP tools in your Claude Code version).
4. Remove or disable it after the job; record enable/disable in the job log.

### 8.3 Secrets (#40)

- Keys only in the environment or a user-level config outside the repository, following [N19] ("never written into your project"), and in production only in the worker's allowlisted secret store (`07_end_to_end_pipeline_instructions/07_SECURITY_CREDENTIALS_and_SKILL_ADMISSION.md` §2).
- No key in prompts, briefs, `beats.json`, `estimate.json`, logs or asset manifests; bearer or signed URLs are never persisted (`07_end_to_end_pipeline_instructions/07_SECURITY_CREDENTIALS_and_SKILL_ADMISSION.md` §3).
- Preflight and the linter scan for key-like strings (doc 01 §9; doc 04 §8 L22).
- Rotation on any exposure; incident recorded.

## 10. Character consistency and the no-science-from-images rule

### 10.1 Character consistency (#48)

[V4-MP]: keep the recurring hero identical "by using an earlier image of them as a reference" and make "pose variants of the same character". Procedure [Recommendation]:

1. Generate (or commission) one **canonical hero image**; approve it at the first collage storyboard gate; store it with its SHA-256 in the AssetManifest.
2. Every later cutout request attaches the canonical image (and the approved grid) as reference, per [V4-MP]'s template ("Match the character designs and art style of the attached storyboard sheet").
3. Ask for **pose variants** (pointing, cheering, waving, thinking) of the same character rather than new characters.
4. Reviewers compare each new cutout with the canonical image at asset review; a drifted cutout uses the approved regeneration allowance, then escalates.
5. Where possible, reuse approved cutouts across lessons (asset library) instead of regenerating.
6. Whether Higgsfield exposes seeds or other consistency controls is not verified; do not rely on them.

### 10.2 Never labelled science from an image model (#54)

- Image prompts always include "no text, no letters, no numbers, no labels, no formulas" ([V4-MP]'s cutout template already says "no text").
- Text, tags, numbers, arrows with meaning, axes and formulas are built in code from fixtures ([V4-MP]: "Built in code, not generated as images").
- Generated imagery is never a scientific diagram (no labelled anatomy, circuits, molecular structures, graphs). Those come from SVG/Manim/molecule/biology skills.
- Asset review rejects any generated image containing glyphs; an automated text detector can assist (tool to admit and pin; verify) but the human check is the gate.
- Decorative imagery must not contradict the science (a "cute" atom picture with a wrong electron arrangement is rejected even if unlabelled) (report §7.13).
