## 1. How the Skills are laid out

```text
narration_system_v1/skills/
└── examleaf-<skill>/
    ├── SKILL.md                # frontmatter (name, description) + Contract, Execution, Safety gates,
    │                           #   Acceptance and tests, Cost and fallback, References
    ├── evals/cases.json        # one positive + one negative case; status "authored-not-agent-executed"
    ├── references/README.md    # "Use the shared guides and exact provider contracts. Do not copy stale API snippets into each Skill."
    └── templates/handoff.json  # {skill, input_artifact_hashes[], output_artifacts[], issues[],
                                #  human_review_required: true, paid_calls_authorized: false}
```

All 15 `SKILL.md` files were generated by `scripts/build_docs.py` from the rows of `research/custom_skills.csv` (verified: every CSV field appears verbatim in the matching `SKILL.md`).

## 6. How to install and use these Skills (step by step)

1. **Keep one canonical source.** `AGENTS.md`: "Canonical skills/ is the source; install only selected tasks in the client-specific discovery directory. Do not load every public/private Skill at once." `research/Public_Narration_Directory.md`: "Use one canonical source folder and controlled sync, not diverging copies."
2. **Pick only the Skills the current task needs** (e.g. a voice-direction pass needs #7, #8, #9 — not all 15).
3. **Copy each selected folder** into the client's project-local discovery path:
   - Claude Code: `.claude/skills/<skill>/SKILL.md`
   - Codex: `.agents/skills/<skill>/SKILL.md` ("check client-specific current behavior")
   ```bash
   # from your ExamLeaf project root; example for the voice-direction trio
   mkdir -p .claude/skills
   cp -R /path/to/05_narration_system/narration_system_v1/skills/examleaf-voice-acting-director .claude/skills/
   cp -R /path/to/05_narration_system/narration_system_v1/skills/examleaf-pacing-controller   .claude/skills/
   cp -R /path/to/05_narration_system/narration_system_v1/skills/examleaf-stem-pronunciation  .claude/skills/
   ```
4. **Keep the referenced files reachable.** Each `SKILL.md` references `../../docs/...`, `../../research/...` and `../../configs/narration.schema.json`, i.e. it expects to sit two levels below the narration repo root. If you install it elsewhere, also copy (or re-point) those four references.
5. **Separate roles** (`CLAUDE.md`): "Keep script authoring, provider access and release roles separate. Public Skills supply package guidance; ExamLeaf contracts own science and pedagogy." `LICENSING_AND_SECURITY.md`: "Research agents and scriptwriters should not have publishing or billing credentials."
6. **Hand off between Skills with `templates/handoff.json`** — fill `input_artifact_hashes`, `output_artifacts`, `issues`; leave `human_review_required: true`; `paid_calls_authorized` stays `false` unless a budget-reserving worker (not the Skill) authorises a call.
7. **Validate outputs with the code**, not with the Skill's own conclusion: `PYTHONPATH=src python -m examleaf_narration.cli validate <plan.json>` and `PYTHONPATH=src pytest -q` (see `INSTRUCTIONS_narration_pipeline.md`).
8. **Before relying on any Skill in production, evaluate it** with Anthropic's `skill-creator` (trigger tests, functional evaluations, regression cases) — "A polished `SKILL.md` is not evidence of effectiveness" (message 12 §4). This has not been done yet.

## 7. Public narration Skills — reuse decisions (message 12 §4)

The downloadable directory covers **28 repositories, APIs, model families, and audio tools**, classified by their actual function (full list in §8).

| Resource | What to reuse | What not to assume |
|---|---|---|
| **ElevenLabs Skills** | `text-to-speech`, `speech-to-text`, `voice-changer`, `voice-isolator`, selective dubbing | A Skill installation does not approve a voice or establish scientific pronunciation |
| **ElevenLabs MCP** | Supervised auditions and asset operations | MCP is not a permission sandbox or durable production queue |
| **Cartesia Skills** | `cartesia-api` | A conversational-agent platform is not necessary for prerecorded lessons |
| **Cartesia MCP** | Optional development/audition interface | Production should still have controlled SDK/API workers |
| **Remotion Skills** | Audio timing, captions, rendering, multimedia guidance | Remotion composes audio; it is not itself a speech model |
| **Manim Voiceover** | Voiceover/bookmark synchronization patterns | Its service adapters do not validate the scientific narration |
| **Anthropic Skill Creator** | Trigger tests, functional evaluations, regression cases | A polished `SKILL.md` is not evidence of effectiveness |
| **OpenAI speech Skill** | Selected CLI and workflow patterns | Its model defaults require lifecycle review |

The official ElevenLabs repository currently provides ten relevant product Skills and documents both Python and JavaScript SDK usage. Its JavaScript guidance distinguishes the current scoped package from an outdated package name. Cartesia explicitly distinguishes its Skills, documentation, SDKs, and optional MCP interface. That separation should remain intact in ExamLeaf's architecture.

### Installation policy (message 12 §4)

> Confirm origin → inspect scripts and permissions → review licences → pin the selected revision → test in isolation → enable only the needed components.

Do not run unreviewed shell installers, install entire collections indiscriminately, or give a script-writing agent unrestricted synthesis and publishing credentials. For bulk narration, use **SDK/API workers with explicit budgets and persistent job records**. Use MCP primarily for supervised development and auditions.

### Install and update protocol (`research/Public_Narration_Directory.md`)

Read the repository and selected SKILL.md, scripts, package manifests, network endpoints and credential access first. Pin a real commit and dependency lock; do not mistake a file blob SHA for a commit. Copy only approved Skills into a project-local path. The public convenience commands `npx skills add elevenlabs/skills`, `npx skills add cartesia-ai/skills`, and `npx skills add remotion-dev/skills` are discovery/install routes, not audit procedures. **This package did not execute them.**

MCP adds tool access inside authoring clients. SDK/REST workers own unattended synthesis, job IDs, secret handling, spending limits and retry state. A Skill is neither a TTS model nor a runtime permission sandbox. `LICENSING_AND_SECURITY.md`: "Do not run unreviewed curl-pipe-shell installers. Skills are untrusted instruction/code packages, not permission boundaries."
