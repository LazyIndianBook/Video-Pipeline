# Implementation roadmap
## Phase 0 — freeze contracts, 3–5 working days (estimate)
Assign academic owner per subject. Obtain syllabus/rights evidence. Review this scaffold and reject unsupported assumptions. Pin dependencies and design tokens. Select one voice audition corpus. Gate: everyone agrees on source/claim/scene/approval meaning.
## Phase 1 — port golden fixtures, 1–2 weeks (estimate)
Install audited HyperFrames and optional Remotion in isolated environments. Reproduce the same four science fixtures without rewriting the models. Benchmark both; select one. Add reusable equation, graph, circuit, molecule and process-state components. Gate: same correct scientific states across layouts and repeated builds.
## Phase 2 — audio + four complete lessons, 2–3 weeks (estimate)
Implement native TTS estimate/submit/cache/poll/fetch, actual forced alignment and sentence-level regeneration. Write and approve full scripts and exercises. Build pronunciation dictionaries and native-language review. Produce four complete pilots with timed reviewer records. Gate: academic and full-video approval, phone-readable rendering and fair practice pauses.
## Phase 3 — controlled batch, 2–3 weeks (estimate)
Durable orchestration, Postgres, staged object storage, secret isolation and retry/cancel/resume. Real provider failure injection in staging. Trial 20–30 lessons. Add independent vertical Shorts and reviewed title/CTA metadata. Gate: failure/repair/cost targets demonstrated, not assumed.
## Phase 4 — scale incrementally
Increase workers only with queue/CPU/storage observations. Expand component and source libraries, not arbitrary per-lesson code generation. Introduce additional languages after real supported-voice/native-review tests. Review student outcomes and board updates. Publish solely approved hashes; keep acquisition/entitlements separate from media production.

Planning schedule assumes dedicated engineering and available subject reviewers. It is not a committed calendar or evidence that the full system can be delivered without further work. Native app, Kubernetes, full self-hosted LLM serving, large MCP fleets and a broad Blender asset pipeline are not launch prerequisites.
